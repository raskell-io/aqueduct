# Crash harness: file log, Apple M4

- **Date:** 2026-10-31
- **Tool:** `cargo xtask crash --kills 1000` (xtask/src/crash.rs), `FileLog` with 64 KiB segments
- **Machine:** Apple M4, internal SSD, APFS, macOS 26

| | |
|---|---|
| kills (SIGKILL at a random 5 to 85 ms after start) | 1,000 |
| duration | 98.9 s |
| records acknowledged | 171,332 |
| acknowledged records lost or altered | 0 |
| records durable beyond the last acknowledgement (allowed) | 34,188 |

Each kill was followed by recovery and a full check of the log: every acknowledged record present, in
order, with exactly the expected content, and nothing else.

The harness itself was checked with an injected bug (`AQUEDUCT_CRASH_BUG=ack-before-write`, which
acknowledges before writing): it reported lost acknowledged records at the fourth kill.

Scope: this covers process crashes on a real disk, during writes, syncs and segment rotations. It does not
cover power loss, because the OS page cache survives a killed process; the simulator's disk model covers
lost and torn unsynced writes, and a VM-level power-loss harness is future work.
