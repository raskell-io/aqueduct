# Aqueduct v0.4.0: the cluster preview

The first tagged release. `0.4` stands for phase 4 of the [build brief](../../BRIEF.md), the cluster. Everything
built in phases 0 to 3 is included.

**This is a preview, not a production release.** The protocol and the history format are drafts until phase 5,
nothing is published on crates.io, PyPI or npm, and the cluster has not yet been drilled on real machines.

## What is in it

**Embedded engine (phases 0 and 1).** Durable code workflows in Rust, journaled and replayed
deterministically. The log is a file with group commit and state lives in redb. Timers, signals, child runs,
sagas and cancellation are included. Every change is checked by a deterministic simulator and a crash harness.

**Procedures and agents (phase 2).** Procedures are short, typed Starlark programs. They are replayed against
past runs before a named person approves them. Agent steps are bounded and budgeted. A version registry
records each procedure's lifecycle, and an MCP server lets agents propose and validate procedures.

**Single server and the open protocol (phase 3).** `aqueduct server` speaks HTTP and gRPC. Step workers and
workflow workers can be written in any language; the Rust, Python and TypeScript SDKs pass the conformance
suite. The server also provides namespaces, tokens, TLS, a web console at `/console`, and
`aqueduct migrate`, which moves an embedded directory to a server.

**Cluster (phase 4):**

- Partitions are replicated by Aqueduct's own Raft, with snapshots, membership changes, pre-vote and
  leadership transfer.
- Each request is routed or forwarded to its partition's leader.
- Leaders are spread across servers, and replicas can be moved through the admin API.
- Servers can be upgraded one at a time; neighbouring minor versions interoperate.
- Servers authenticate each other with mutual TLS.
- Histories are archived to a directory or to S3-compatible storage.
- Retention forgets runs that ended long enough ago ([ADR 0066](../adr/0066-retention.md)).
- `aqueduct drill` drives a failover drill.
- A simulated five-server cluster passes 100,000 seeds every night.

## Downloads

Each archive below holds the `aqueduct` binary (server, CLI and drill), the README and the licences. A
`.sha256` file comes with each one. Check an archive before you use it:

```sh
shasum -a 256 -c aqueduct-v0.4.0-<target>.tar.gz.sha256
```

| target | for |
|---|---|
| `x86_64-unknown-linux-gnu` | Linux on x86-64 |
| `aarch64-unknown-linux-gnu` | Linux on ARM64 |
| `aarch64-apple-darwin` | macOS on Apple silicon |

To use the library, depend on the repository at this tag:

```toml
aqueduct = { git = "https://github.com/raskell-io/aqueduct", tag = "v0.4.0" }
```

## Not done yet

- A failover drill and measurements on real machines ([the procedure](../failover-drill.md)), and testing by
  anyone outside the project.
- Stable formats: these come in phase 5. Data written by 0.4 may not be readable by a later 0.x.
- Packages on crates.io, PyPI and npm.
- OIDC or JWT, and client certificates for clients and workers.
- Retention per namespace (today there is one policy per server).

See [what is not done](../../README.md#what-is-not-done) for the full list.
